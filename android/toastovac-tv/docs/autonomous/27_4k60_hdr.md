### Dominant bottleneck (P2.4)

**Box display refresh mismatch.** The active display mode is 59.94 Hz
(`activeMode=59.94 Hz`, `defaultModeId=42` = 3840×2160@59.94). A 60.00 fps
stream cannot be drained by the decoder/display indefinitely: the ~0.06 fps
excess accumulates a backlog (measured `framesIn − framesOut` gap fluctuating
1800–2600 frames), and when the MediaCodec input queue fills, the receiver
stalls → TCP backpressure → mux `sendall` blocks → sentFps collapses; the
decoder then drains the backlog in bursts (86 fps) → oscillation. Not the
encoder (sustains 60), not the bsf (P50 0.2 ms), not the AU assembler
(queue 0), not Python (sent ≈ produced until the stall).

### Single fix applied (rerun once, per P2.4)

Pace the stream at the display rate: `--fps 60000 --fps-den 1001`
(16.6833 ms/frame) — engine now supports fractional frame rate
(`FrameRateExtN=60000/FrameRateExtD=1001`). `cast.scene fps=59.94` maps to
this exactly; the decoder never accumulates a rate-mismatch backlog.
